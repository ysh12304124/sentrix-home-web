# 2026-08-25 检索图片为空故障审计

## 结论

故障不是图片 URL 或前端渲染单点故障，而是上游检索链路的两个条件叠加：

1. 153 上的 8091 进程未启用 canonical time/place/person 检索，带“馆陶县+婚礼”的问题落入纯语义检索，前 30 个候选实际来自邯郸永年区的家庭照片；视觉验证器正确地将 30 张全部判为 rejected，于是公开预览被过滤为空。
2. 上一轮取消 100QA 时，8771 取消流程停止了 8100；在模型不可用期间验证器连接拒绝，且旧的“验证完成但零支持也清空 preview”逻辑会把真实候选隐藏，造成评测界面几乎无图。

## 已修复

- 启用并设为默认的 canonical 检索：地点/时间/人物约束先进入结构化事件候选，再保留语义检索；`馆陶县婚礼` 已复现召回 2 张正确照片（2017-09-27）。
- 验证器只有在存在 `supported` 时才缩小 preview；零支持、验证失败或模型暂时不可用时保留有界候选，证据集合仍保持为空，避免把候选误报为证据。
- prior result-set 路径同步修正 `candidate_only/limited` 语义。
- 评测前端在没有 evidence/predicted 图片时展示最多 6 张 retrieved candidates；候选与回答证据仍分开统计。
- 重启 8771，恢复 8771 页面和 API；重启 8091，恢复 8100 gemma4-12b-it。

# 语义实体层与语义目录界面设计

## 目标

将地点、物品和情绪改造成可控的两层语义记忆：模型先从简单、覆盖日常生活的主类词表中选择，再从对应的细节词表中多选。语义组只作为浏览、筛选和检索投影，不删除或物理合并原始实体。

网页默认呈现语义段和原始证据缩略图，不把文件名、内部 ID、属性键、模型名和置信度数字作为主内容。

## 已确认的数据契约

### 地点

- 每个 Observation 选择一个地点主类。
- 允许选择 `其他或不确定`，不得在无法判断时强行归类。
- 细节为受控多选标签；模型自由文本保留在 Observation 证据中，不直接生成实体。
- GPS 只作为 Asset 的原始位置属性和证据，不作为地点实体名称或语义组名称。
- 地点实体组按主类形成；具体地点描述、GPS、用户别名和原始文本作为组内证据或属性。

地点主类 v1：

```text
居住空间、餐饮空间、商业空间、公园与花园、滨水空间、山地与自然景观、
街道与广场、交通空间、文化与展览、运动与休闲、演出与活动、办公与学习、
医疗与公共服务、宗教与纪念、工业与工程、住宿空间、农场与乡村、其他或不确定
```

地点细节示例：

```text
室内、室外、客厅、卧室、厨房、阳台、门口、正餐、咖啡或茶、烘焙、
有餐桌、露天座位、商场、超市、市场或摊位、展厅、舞台、候车区、酒店房间、
多人停留、开放空间、自然环境
```

### 物品

- 一个 Observation 可以包含多个物品记录。
- 每个物品记录选择一个主类，并可有多个细节标签。
- OCR 文本、模型自由描述和未确认的物品名称保留为 Observation 证据。
- 不从物品出现推断归属、所有者或人物关系。

物品主类 v1：

```text
食品与饮品、餐具与容器、电子设备、家具与家居、服饰与配件、植物与花卉、
动物与宠物、交通工具、建筑与公共设施、文字与标识、玩具与娱乐、书籍与文具、
礼物与纪念物、其他或不确定
```

### 氛围

- 名称从“情绪”改为“氛围”。
- 一个 Observation 可以选择多个氛围主类。
- 氛围只描述可观察的画面状态，不写成某个人的心理事实或关系事实。
- 细节描述光线、色彩、空间感、人群密度和可观察活动状态。

氛围主类 v1：

```text
温馨、热闹、轻松、平静、安静、活跃、忙碌、庄重、节庆、自然开阔、其他或不确定
```

氛围细节示例：

```text
明亮、昏暗、暖色光线、冷色光线、空间开阔、空间拥挤、多人聚集、少人、
画面整洁、画面繁杂、庆祝活动、观看活动、休息状态、自然光
```

## 语义组规则

1. 模型选择的主类是默认浏览入口。
2. 同一主类的不同具体描述进入同一语义组；细节作为组内标签和筛选条件。
3. 例如“餐厅”“咖啡馆”“茶室”进入“餐饮空间”，分别保留“正餐”“咖啡或茶”等细节。
4. 原始实体、原始名称、Observation、Event、Asset、GPS 和修订记录必须继续可追溯。
5. 不跨 MemorySpace 分组。
6. `其他或不确定`只作为兜底，不创建大量新的默认实体。
7. 语义摘要只能基于组内已确认的主类、细节和证据生成，不补充未经观察支持的地点、人物或活动。

## 网页信息架构

### 语义目录

语义目录分为“人物总结、地点、物品、氛围”几个区域。人物仍使用确认过的人物证据；本设计只改变非人物语义实体的主展示方式。

非人物卡片默认只包含：

- 一至三张原始证据缩略图；
- 语义主类名称；
- 主要细节标签；
- 一段基于证据的简短语义说明；
- 打开相关证据的动作。

卡片不默认显示文件名、Asset ID、Observation ID、属性键、模型来源、置信度数字或精确 GPS。

示例：

```text
[原始图片] [原始图片] [原始图片]

餐饮空间
室内 · 正餐 · 有餐桌 · 多人用餐

这些记录主要呈现与用餐、饮品或餐桌活动有关的场景。
查看相关证据
```

### 语义详情

点击语义卡进入详情面板或详情页，顺序固定为：

1. 主类名称和语义摘要；
2. 细节标签和按标签筛选；
3. 原始证据缩略图网格；
4. 点击后打开原始 Asset；
5. 可选的证据审计详情。

证据审计详情才显示文件名、时间、GPS、Observation ID、模型原始输出和版本信息。原始图片始终是证据入口，不能用生成缩略图或只有文字的卡片替代。

## API 与存储方向

- 在 Observation 的规范化输出中保存主类、细节、多值物品和氛围字段。
- 在实体属性中区分 `semantic_primary`、`semantic_details`、`raw_labels` 和 `evidence_ids`。
- 地点属性至少区分 `geo`、`scene_type`、`visual_place_descriptions` 和用户别名。
- 语义组 API 返回主类、细节聚合、语义摘要、代表性原始证据和成员数量；不把内部实体 ID 放入默认文字。
- 重新索引时只重建派生语义投影，不能覆盖用户属性或删除原始证据。

## 验收标准

### 语义处理

- 新图片的地点主名称不再使用 GPS 字符串。
- 图片无法判断地点时进入 `其他或不确定`，不伪造具体地点。
- 餐厅、咖啡馆、茶室可以进入同一个“餐饮空间”语义组，并保留具体细节。
- 同一图片可以同时保留多个物品和氛围标签。
- 原始自由描述仍能从 Observation 和原图证据中打开。
- 重建前后用户维护属性、MemorySpace 隔离和原始证据链接不变。

### 网页展示

- 语义目录主视图不显示文件名、Asset ID、Observation ID、属性键和置信度数字。
- 每个语义组都有至少一个可打开的原始证据缩略图时才进入默认展示。
- 语义详情同时呈现主类、细节语义和原始证据。
- 证据审计入口仍可查看完整技术信息。
- 地点、物品和氛围可以按细节筛选，不需要用户阅读内部实体标签。

## 暂不纳入

- 不把地点实体物理合并成一条记录。
- 不通过联网逆地理服务把 GPS 转成 POI。
- 不让模型自由创造无限主类或细节标签。
- 不由地点、物品或氛围自动推断人物关系、所有权或心理状态。
- 不修改 Agent 的规划、检索和回答策略；本任务只建设语义实体层和网页展示。

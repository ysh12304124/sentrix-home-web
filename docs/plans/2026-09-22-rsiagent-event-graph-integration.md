# RSIAgent 方法在事件图记忆中的整合方案

## 目标与边界

本方案只改图记忆构建、事件摘要和图检索，不改 Agent 主循环、Judge、评测数据、召回率评分口径或 vLLM 配置。最终检索仍以远程 main 仓库的 top-k=18 口径为准。

RSIAgent 的可借鉴部分是“广泛探索 → 针对失败深入探索 → 独立验证 → 批量提交 → 冻结评测”的记忆协议，而不是直接复制它面向软件操作 Agent 的代码。

## 现状问题

1. 关键帧先直接生成 EVENT，事件摘要主要依赖已有 `event_id`；同一真实事件跨 clip 时容易被拆散。
2. 事件摘要没有稳定聚合时间、地点、人物、活动和合法媒体来源，导致关键帧中的信息没有成为事件级检索字段。
3. 图检索主要从普通检索结果做后置扩展，普通检索漏掉事件时，图检索缺少有效种子。
4. 图候选受到有限配额和最终 head 截断影响，图虽然命中但不一定进入 top-k=18。
5. 中间 webp、face crop 等非最终证据没有统一的媒体准入层。

## 方案一：事件草稿与验证后提交

新增临时事件草稿层，不让关键帧信息直接进入正式图：

```text
FrameObservation → EventDraft → VerifiedEvent → GraphSnapshot
```

`EventDraft` 聚合：

- 时间候选及支持帧数
- 地点候选及支持帧数
- 人物、活动、关系和对象
- 原始照片、视频关键帧、视频的来源 ID
- 摘要候选和字段冲突

只有通过一致性校验的事件才进入正式图。低置信度或字段冲突的事件进入隔离状态，不参与高置信度检索。

事件合并不再只依赖 `event_id`，而使用时间、地点、人物重叠、活动语义和视觉相似度的组合得分，解决同一婚礼事件被不同 clip 拆散的问题。

## 方案二：RSIAgent 式两阶段构建

### Broad Build

并行抽取所有关键帧、图片和视频中的时间、地点、人物、活动、关系及媒体归属，建立完整候选事件覆盖。

### Deep Repair

从上一轮测评中选择召回率为 0、回答质量为 0、图新增命中失败的题目，针对缺失字段重新抽取。例如“天台婚礼迎宾展架”重点补抽地点、婚礼活动、迎宾展架、拍照和日期关联，而不是重新盲目生成全相册摘要。

### Frozen Evaluation

图构建完成后生成固定 `graph_version` 和 hash。评测期间禁止在线写入图，确保指标反映固定图版本的真实效果。

## 方案三：事件先召回，媒体后展开

检索流程改为：

```text
问题解析 → 事件节点召回 → 时间/地点/人物/活动验证 → 展开合法媒体 → top-k=18
```

最终媒体只允许原始图片、视频关键帧和视频。`face_crop`、`faceid`、`event_event_*.webp`、拼图和临时缩略图只能作为内部中间产物，不能作为最终证据。

## 方案四：逐题图效果追踪

每道题记录：

- 普通检索候选集
- 图检索新增候选集
- 图新增 GT 数量
- 图移除 GT 数量
- 进入最终 top-k 的图候选
- 被媒体准入策略排除的候选及原因
- 事件节点和边路径

最终区分：图没召回、图召回但被截断、图召回但被媒体过滤、图召回且进入 top-k、图导致回归。

## 实施顺序

1. 修复实时评测指标显示，并建立不改图逻辑的全量基线。
2. 增加合法媒体准入策略。
3. 实现 EventDraft 和事件属性聚合。
4. 实现事件合并和验证后提交。
5. 将图检索改为事件级召回后展开媒体。
6. 用固定小样本回归，再跑 500 题，最后跑全量 1167 题。
7. 以最终 top-k=18 的真实召回率、图新增 GT 数、图回归数和回答质量共同判断版本，不为了图效果虚高而改变评测口径。

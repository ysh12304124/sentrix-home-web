# Sentrix Home / PhotoBench 测评项目简介

## 一、项目定位

本项目是面向多模态个人记忆系统的全量评测与分析平台，用于验证照片、视频、关键帧、人物、地点、时间和事件等信息，能否被正确建立、检索、引用并转化为可靠回答。

项目由两部分组成：

- **Sentrix Home 算法服务**：负责媒体导入、图片和视频解析、关键帧处理、OCR、Embedding、人物聚类、事件组织、记忆存储和自然语言检索。
- **PhotoBench 测评平台**：负责加载 QA 数据集，调用模型和工具执行全量问答，调用 Judge 评分，并保存逐题回答、检索结果、证据、工具轨迹和性能指标。

## 二、系统链路

```text
照片 / 视频
    ↓
媒体解析、OCR、关键帧和人物处理
    ↓
场景图、事件记忆、时间/地点/人物关系
    ↓
检索工具返回候选媒体和证据
    ↓
Agent 组织证据并生成回答
    ↓
Judge 评分、指标统计和错误定位
```

测评平台不是单纯测试模型输出，而是检查完整链路：

```text
原始媒体 → 场景解析 → 事件记忆 → 证据规则 → Agent回答 → Judge结果
```

## 三、记忆分层

| 层级 | 内容 | 主要作用 |
|---|---|---|
| L0 | 原始图片、源视频、视频关键帧 | 保存可检索的原始媒体和视频时间片段 |
| L1 | 场景图、视觉描述、OCR、人物和空间关系 | 将媒体转换成可理解的场景信息 |
| L2 | 事件、时间、地点和跨媒体关联 | 将多个媒体组织成连续事件记忆 |
| L3 | 查询目标、证据需求和引用规则 | 判断回答需要哪些时间、地点、人物或场景证据 |
| L4+ | Agent 回答、回答证据和 Judge 评分 | 生成最终答案并验证回答质量 |

其中，关键帧和原始图片不能只看“是否创建”或“是否被接口返回”，而要结合测评结果判断：

- 返回证据后回答正确：有效；
- 返回相近证据后部分正确：可用；
- 返回证据后回答错误：无效；
- 没有返回 GT 媒体：未命中，不计为有效。

## 四、评测平台功能

PhotoBench 目前支持：

- 全链路建库、复用已有相册、仅构建相册三种运行模式；
- 图片、视频和混合多模态 QA 数据集；
- vLLM OpenAI-compatible 模型服务；
- Agent 工具调用、检索候选、图片观察、OCR 和证据账本追踪；
- Judge 2 分、1 分、0 分和未评分统计；
- 记忆分层、检索召回、关键帧、事件证据和最终回答指标；
- 单题查看图片、视频、关键帧、回答、工具参数、工具结果和证据链；
- 原始创建链路与测评生效链路对比；
- 评测结果导出和历史运行对比。

## 五、当前指标口径

项目将指标分成三类，避免把工程覆盖率误认为回答正确率：

1. **规模指标**：例如原始媒体创建量、事件数量、关键帧数量，只表示记忆库规模。
2. **测评链路指标**：例如图片 Recall、关键帧父级 Recall、关键帧返回 Precision、工具成功率和证据闭合率，用于定位检索和工程问题。
3. **结果正确性指标**：以 Judge 的最终回答结果为准；Exact Accuracy 表示完整回答正确率，部分正确单独统计。

当前全量运行基线为 487 道 QA，Judge 结果为：正确 97、部分正确 90、错误 299，Exact Accuracy 为 19.9%。这些结果用于定位记忆检索、证据使用和回答生成问题，不代表单一模型能力结论。

## 七、项目目标

项目最终目标不是只提高一个分数，而是建立可解释、可复现的多模态记忆评测体系，能够回答以下问题：

- 原始图片和关键帧是否被正确检索；
- 时间、地点、人物和事件是否被正确关联；
- 返回的证据是否真正支持回答；
- 错误来自媒体处理、图谱、检索、证据组织还是模型回答；
- 优化后指标提升是否来自目标模块，而不是偶然波动。
